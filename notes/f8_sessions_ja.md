# F8 摩擦の床は個体の値か、セッションの値か（2026-10-12）
問い：グリッパの摩擦の床（floor/d2_analyze.py の「個体カード」）は、個体ごとに決まり日をまたいでも変わらない値なのか。それとも、温まり具合・摩耗・組み直しといったセッションの状態で変わる値なのか。
判定：同じ個体のデータセットどうしが水準で ±15 % 以内にそろえば結果 1（個体の値）、それより広く散れば結果 2（セッションの値）。

コードは sim_demos/floor/f8_sessions.py（d2_analyze.py を import して使い、d2_analyze.py には手を入れていない）。表の全文は notes/f8_table.txt（<scratchpad>/d5/f8_table.txt の写し。再実行した表と 1 バイトも違わない）。

印は次の 3 つ。
- 【測】実データで測った値
- 【計】そこからの計算
- 【仮】仮定

確からしさは 高 / 中 / 低。特に断らない数は「閉じる向きに 40〜100 deg/s で定常に動いているときの |τ| の中央値」（d2 カードの move_close_40。以下「閉じ動摩擦」、単位 Nm）。n はフレーム数 / エピソード数で、「!」は 30 フレーム未満（n が足りない）。日付は Hugging Face へのアップロード時刻（UTC）で、録画時刻ではない。

## 結論
1. **個体 A は結果 2：±15 % を超えて散る**【計、中】。
   - A と判定した 6 データセット（n ≥ 30）の閉じ動摩擦は **0.608〜0.916**。max/min 1.51、CV 0.157、半幅/平均 0.22。アップロードは 03-04〜03-14。
   - アップロードの束（以下セッション）で数えると、n ≥ 30 の 9 セッションで **0.608〜0.852**。max/min 1.40、CV 0.123、半幅/平均 0.17。
   - 顎の角度の混ざり方をそろえても 1.51 / 1.44 で、結論は変わらない。
   - n < 30 のセルも入れると 12 セッションで 0.608〜0.979、max/min 1.61。
   - 確からしさを「中」にとどめた理由は二つ。個体の同一性と録画日が仮定であること（6 と「仮定と確からしさ」）。
2. **散り方の形：束の中と同じ日の束どうしはそろい、束の境で段がつく**【計、中〜高】。
   - **100ep-v2**：03-06 に上げた 2 束は 0.779 [0.745, 0.803]（69/31）と 0.769 [0.735, 0.808]（83/40）で、比 1.013。03-10 に上げた第 3 束は **0.637 [0.628, 0.647]（112/43）**、−17〜−18 %。
   - **blue-20ep**：同じ境で 0.789 [0.728, 0.840]（32/14）→ **0.652 [0.630, 0.698]（42/13）**、−17 %。95 % 区間は重ならない。
   - **束の中**：100ep-v2 の前半 → 後半は +2.0 / +6.5 / −0.5 %。奇数 / 偶数エピソードの差は 0.5〜5.7 %。
   - **日ごと**：03-04（50ep b2 0.852）、03-06（0.691〜0.789、4 セッション）、03-10（0.637・0.652）、03-14（0.608・0.625）と下がり、日の間で値の幅は重ならない。
   - **同じ日でも散る**：03-06 に上げた 4 セッションどうしで max/min 1.14（orange 0.691 と blue b1 0.789）、つまり ±6.5 %。
   - **ほかの束の中の漂い**：50ep b2 の前半 → 後半は 0.930! → 0.779!（−16 %、各 17〜18 フレーム）。cube-organization-v2（一度に上げた 120 エピソード）は、角度をそろえると四分位で 0.558 → 0.641（+15 %）。ただし角度をそろえない p50 では 0.618 → 0.645（+4 %）にとどまる。
3. **カードのほかの項目も同じ境で動く**【計、中】。
   - **引いて静止（push-open）**：顎の角度をそろえる（5° 区間 3 つの中央値の平均）と、
     - 100ep-v2：0.873 [0.670, 0.943] / 0.856 [0.797, 0.898] → **0.545 [0.527, 0.615]**（−36〜−38 %）。3 つの区間（−45 / −40 / −35°）のどれでも下がる（1.170 / 1.131 → 0.603、0.847 / 0.769 → 0.574、0.603 / 0.667 → 0.457）。
     - blue：1.017 [0.899, 1.092] → **0.759 [0.704, 0.805]**（−25 %）。
     - 同じ日の束どうしの差は 2〜6 %（50ep 0.916 / 0.865、100ep-v2 0.873 / 0.856）。
   - **角度をそろえない p50 ではこの段は見えない**（0.730 / 1.013 / 0.847）。開く向きの力は開端に近いほど大きく（F1）、束ごとに開いた幅が違う（開端 −45.7 / −55.7 / −51.7°）ため。
   - **動いて開く**：5° 区間 1 つだけの比較で、100ep-v2 は 0.974 / 1.053 → 0.720（9〜12 フレーム）、blue は 1.228 → 0.955（各 6 フレーム）。向きは同じだが n が薄い。
   - **押して静止（push-close）の p50**：セッションごとの 95 % 区間が [0.007, 0.574] のように広く、セッション差は判定できない。p90 は n ≥ 30 の 5 つで 0.476〜0.652（×1.37）。
   - **把持内のばらつき s**：A のセッション（dof 14〜180）で 0.0298〜0.0817（×2.7）。同じ日の 100ep-v2 b1 / b2 でも 0.0566 / 0.0817。
4. **個体どうしの差は、セッションによる散りより大きく残る**【計、高】。
   - A の最小セッション 0.608 に対して、B（newarm）は 0.203 [0.188, 0.208]（69/27）で 3.0 倍。A の最大セッション 0.852 とは 4.2 倍。
   - ただし「A は B の 3〜4 倍」は、日によって ±20 % 動く A と、1 セッションしか読めない B の比として読むべき数。
   - s の比は、カードの 0.066 / 0.019 = 3.5 倍が、A の最小セッション（blue b2 0.0298、dof 25）と比べると 1.6 倍まで縮む。
5. **個体 B は判定できない**【計、低】。
   - n ≥ 30 で読める B のセッションは newarm（03-18）だけ。
   - operator-50ep（03-23）の閉じ動摩擦は 0.164! [0.144, 0.173]（23/11）。newarm との比 1.24 で区間は重ならないが、n が 30 に届かない。
   - 静止の押し・引き（p50 と p90）の newarm との比は 1.22〜1.27。n は 238〜2,495 フレームあるが、エピソード区間はとっていない。
   - operator-50ep の範囲は −50.5..1.8° で、newarm の −45.1..0.5° と違う。同じ個体かどうかも分からない。
6. **これまでの前提で改めるところ**【計】。
   - (a) **漂いではなく束の段**：100ep-v2 の「セッション内で水準が漂う 0.78 → 0.77 → 0.69 → 0.64」（STATE.md 440〜441 行、notes/precursor_ja.md 58 行）は、0.779 / 0.769 / 0.689 / 0.637（n 64 / 61 / 52 / 87）として再現した。しかし中身は束の境の段である。Q3（ep 84〜116）は束の境 ep 100 をまたぎ、Q4（ep 117〜149）はすべて 03-10 に上げた第 3 束。各束の中ではそろっている（2）。
   - (b) **範囲（開端）では個体を見分けられない**。A のセッションの開端は −40.9〜−55.7° で、操作者がどこまで開いたかで決まる。50ep・orange・yellow・practice・cube-organization の 2 つは、範囲で見ると B 側に入る。
   - (c) **F2-8 が A に数える clean は読めない**。parquet の末尾（footer）が欠けていて、1 フレームも読めない。meta/stats.json のグリッパ角の最小 / 最大（−44.66 / −0.8）とトルクの最小 / 最大（−2.0 / 6.26）が 50ep と一致し、エピソードは 87 / 100 なので、50ep から選んだ部分集合と推定する【計、中】。
   - (d) **2 月の 6 データセットは別の設定で比べられない**。kp_eff は 10.73 / 3.58 / 1.44、閉端は 0 になく、符号が逆のものが 1 つ、末尾が欠けて読めないものが 3 つ。
   - (e) **15〜40 deg/s の帯は摩擦の水準に使えない**。どのデータセットでもフレームの 15〜72 % が |τ| > 1.5 Nm（物を握ったまま動いている）。p50 が 2.8 Nm 台になるもの（cube-organization-full-clear、operator-50ep）もある。40〜100 の帯では 0〜3 %（2 月の別設定を除く）。
7. **d2_protocol_en.md の書き方に及ぶこと**（2026-10-12 23:41 に直した。floor_ja.md F8 も参照）。
   - 「A は 0.70 Nm」は 03-06 の 2 束（約 0.77）と 03-10 の束（0.64）を混ぜた値。A は 0.61〜0.92 Nm（03-04〜03-14 のアップロード）と幅で示すほうが正確。
   - 利用者が測るカードは 1 セッションの読み。P5 の繰り返しは 1 回の実行の中での温まりしか見ない。個体の値と言うには、別の日にもう一度測る必要がある。
   - 「同じ設計の 2 台で摩擦が数倍違う」という主張そのものは残る（4）。

## 方法
- **データ**：gtgando の OpenArm データセット 17 個。meta/ と data/ だけで、動画は取っていない（floor/hf_pull.py --no-video）。
  - 今回取ったもの：practice・table_pickplace_v2・cube_pickplace_v4・openarm_test、それに課題の一覧にない cube-organization-v2 と cube-organization-full-clear-v2。
  - 残りは前から手元にあった。clean・orange・yellow・newarm・operator-50ep は _files.json と大きさが一致することを確かめた。
  - 取らなかったもの：openarm_table_pickplace_v3（0 エピソード）と cube_pickplace_v3（課題の説明で末尾が欠けているとされたもの）。
  - 読み手は /usr/local/bin/python3（CPython 3.10.8、pyarrow 20.0.0、numpy 1.23.5）を -I で、nice -n 10 にして一度に 1 本ずつ。
- **日付**：https://huggingface.co/api/datasets/<owner>/<name>/commits/main（1 ページ 50 件。?p=1, 2, … と追う）と /api/datasets/<owner>/<name>（createdAt、lastModified）から取った。
  - 「Upload folder」のコミットごとに、その版の meta/info.json の total_episodes を読み、どのエピソードがどの束で上がったかを出した。
  - 束のアップロード時刻は、その束のエピソードの録画時刻の上限にすぎない。info.json に日付はなく、parquet の timestamp はエピソード頭からの相対値。
  - cube-organization の 2 つは info.json がなく（upload-large-folder）、エピソードを束に分けられない。どちらも 03-11 13:40 に作られ、データは全部 03-14 に上がった。
- **定義**：カードの値は、すべて d2_analyze.generic() をそのまま通した値。
  - 閉じ動摩擦の帯と静止の押し・引きのマスクは、f8_sessions.py に写して使った。写したマスクがすべてのデータセットと束で generic() の n と p50 に一致することを assert で確かめている。
  - A と B の参照値（0.696 / 0.203、範囲 −55.7..0.3 / −45.1..0.5、静止押し 0.286 / 0.545 と 0.046 / 0.136、s 0.066 / 0.0187）は表に一致して再現した。
- **95 % 区間**：エピソード単位で丸ごと取り直す bootstrap（2000 回、seed 8）の中央値の区間。同じエピソードのフレームは独立でないため、フレームではなくエピソードを単位にした。
- **角度のそろえ方**：
  - 束どうし：同じデータセットのすべての束が埋める 5° 区間（動摩擦は ≥ 5 フレーム、静止は generic() と同じ ≥ 15 フレーム）の中央値の平均。
  - データセットどうし（「角度補正」）：各フレームを、100ep-v2 の同じ 5° 区間の中央値で割る。その比の中央値に 0.696 を掛ける。
- **速度**：40〜100 の帯の中の |v| の中央値と、|τ| を |v| に当てはめた直線の傾きを、表 5 に出した。A のセッションの |v| の中央値は 52〜78 deg/s。傾きは n ≥ 30 のセッションで −0.13〜+0.14 Nm / 100 deg/s で、50ep b2（−1.75、n 35）だけが外れる。03-06 → 03-10 の段は速度の違いでは説明できない。
- **四分位**：帯に 1 フレーム以上入るエピソードの番号の 25 / 50 / 75 パーセンタイルで切る（np.percentile と searchsorted side="left"）。この規則で 100ep-v2 の 0.78 / 0.77 / 0.69 / 0.64 を再現できたので、それを使った。
  - 帯が 120 フレーム（4 × 30）以上あるデータセットだけに当てた。四分位ごとに平均 30 フレームを確保するためで、30 は d2_analyze.py が速度帯に使う「少なすぎる」の線と同じ値。
  - 当てはまるのは 100ep-v2（264）と cube-organization-v2（308）だけで、実際の最小は 52 と 64。3 番目に多い blue は 74 で届かない。
- **個体の割り当て**：3 つの印を分けて出した。
  - 設定：kp_eff が 16.01 の ±2 % 以内、かつ閉端（p99.5）が 0 から 3° 以内。外れれば「別の設定」。
  - 水準：閉じ動摩擦が、A 0.696 と B 0.203 のどちらに対数比で近いか。どちらからも 1.5 倍より離れていれば「other」。
  - 範囲：開端が A −55.7 と B −45.1 のどちらに近いか。
  - 個体 = 設定が同じなら水準の印。範囲の印は個体を見分けない（6b）ので、判定には使っていない。

## 仮定と確からしさ
- **個体の同一性【仮、中】**。データにシリアル番号はない。A かどうかは、持ち主・名前・kp_eff 16.01・閉端 ≈ 0・水準が 0.696 の 1.5 倍以内、から決めた。
  - 水準で選ぶので一部は循環する。窓は 0.46〜1.04 で、散りはせいぜい 2.25 倍までしか入らない（測った 1.51 はその中）。この窓に入る別の個体が混ざっていても見分けられない。
  - 段が同じ名前のデータセットの中（100ep-v2、blue）で起きているのは、同じ個体だという一番強い手がかり。それでも、束の間にグリッパを替えた場合は見分けられない。
- **録画日【仮、中】**。アップロード時刻は上限にすぎない。
  - 100ep-v2 の第 3 束（ep 100〜149）は、ep 99 の直後、03-06 のうちに録られて、上げるのだけ遅れた可能性もある。だから「日をまたいだ段」とまでは言えず、確かなのは「束の境の段」。
  - 100ep-v2 と blue の段は、どちらも 03-10 の朝に 17 分違いで上がった束で起きていて、同じ後のセッションで録られたと読むのが自然だが、未検証。
- **原因【仮、低】**。慣らし（新しいグリッパの摩擦が使うほど下がる）、組み直し、温度、別の個体、操作の違いのどれかは分からない。
  - 操作の違いだけでは説明しにくい。定常の帯（|acc| < 150）で、速度（傾き ≈ 0）と角度をそろえても段は残り、引いて静止も同じ向きに動く。それでも操作の影響は消しきれない。
  - 引いて静止は、止まったときに残ったトルクなので、指令の近づけ方に左右される【仮、低〜中】。
  - 日ごとに下がり続ける並び（0.85 → 0.69〜0.79 → 0.64〜0.65 → 0.61〜0.63）は慣らしと矛盾しないが、03-14 の 2 つは別の課題（cube organization）なので、同じ条件の比較ではない。
- **区間の意味【計、中】**。エピソード bootstrap は、セッションの中でエピソードが入れ替え可能だと仮定している。束どうしの区間が重ならなくても、それは「その束の中の散りより大きい」という意味で、原因までは言えない。
- **4 つの parquet が読めない理由【仮、低】**。PAR1 で始まるのに末尾の magic がなく、pyarrow は「Parquet magic bytes not found in footer」を出す。大きさは Hub の記録と一致するので、上がっているファイルそのものが欠けている。
  - 書き込みが閉じられないまま上げられた失敗と推定するが未確認。後で検索した（2026-10-12 23:41）：同じ文言の失敗が huggingface/lerobot issue #2035（lerobot/svla_so100_stacking / sorting）と複数の v3 データセットのページ（jjziyuz/finaldata、edmos7/eval_multitask_run5_testing、AseelLu/Proton2）に出ているが、読めた範囲では原因と直し方は確認できていない。直してもいない（読めないと表に記しただけ）。
- **clean が 50ep の部分集合【計、中】**。統計値の一致（4 つの値）とエピソード数から推定した。parquet は読めず、フレーム単位では確かめていない。

## 確かめていないこと
1. 録画の日時（アップロード時刻の上限しかない）と、どの束が同じセッションだったか。
2. どのデータセットがどの物理的な個体か（シリアル、組み直しの記録）。
3. 段の原因（慣らし・組み直し・温度・別の個体・操作）。
4. 読めない parquet の原因と直し方（同じ文言の issue #2035 はあるが、原因と直し方は未確認）。
5. B の 2 つ目のセッションの閉じ動摩擦（operator-50ep は 23 フレーム）と、その個体が newarm と同じかどうか。
6. 押して静止（push-close）がセッションで変わるかどうか（区間が広すぎる）。
7. 文献との比較：d2_protocol_en.md が挙げる Hao ら 2021（関節の摩擦は運転中の発熱で漂い、別の日にも試している）の、日をまたいだ変化の大きさはここでは読んでいない（課題の制約で huggingface.co の外に出ていない）。
